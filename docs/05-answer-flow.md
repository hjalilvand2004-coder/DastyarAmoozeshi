# ۵) جریان پاسخ‌دهی مستند

## ۵.۱ قالب پاسخ (بند ۶ مشخصات)

هر پاسخ با شش بخش ثابت نمایش داده می‌شود:

1. **پاسخ کوتاه** — خلاصه مستند از تکه‌های بازیابی‌شده (حداکثر دو جمله در حالت قالبی)
2. **شرایط و استثناهای مهم** — جمله‌های شرطی اسناد (حداقل/حداکثر/باید/نباید/استثنا/مشروط ...)
3. **وضعیت شما (ارزیابی خودکار)** — خروجی موتور قواعد قطعی برای قواعد مرتبط
4. **اقدام بعدی پیشنهادی** — مراحل فرایند اداری منطبق + یادآوری سامانه مقصد
5. **منبع رسمی** — متن عینی تکه‌ها با ارجاع: عنوان سند، نسخه، وضعیت، ماده/تبصره، صفحه (PDF) و لینک
6. **موارد نیازمند تأیید کارشناس آموزش** — مغایرت احتمالی، اطلاعات ناقص پروفایل، قواعد نیازمند تأیید

سه لایه (متن رسمی / توضیح ساده / توصیه شخصی) در همین بخش‌ها تفکیک می‌شوند و رابط کاربری آن‌ها را جدا رندر می‌کند.

## ۵.۲ مراحل پردازش

```
پرسش دانشجو
  ├─ پاک‌سازی (طول ≤ ۱۰۰۰) + محدودسازی نرخ (پیش‌فرض ۲۰ پرسش در ساعت)
  ├─ انتخاب اسناد کاندید (دانشگاه خود کاربر):
  │     status = published و داخل بازه اعتبار تاریخ
  │     اسکوپ (مقطع/رشته/سال ورود) — اگر اطلاعات دانشجو ناکافی باشد، سند حذف نمی‌شود
  │     ولی پاسخ «اطلاعات ناکافی» می‌گیرد و هیچ نتیجه‌ای قطعی تلقی نمی‌شود
  │     (ملغی/منقضی فقط با گزینه صریح کاربر و همیشه با برچسب)
  ├─ امتیازدهی BM25 روی تکه‌ها + آستانه اهمیت
  │     هیچ تکه قوی → «موردی یافت نشد» بدون هیچ ارجاع (سناریوی پذیرش ۵)
  ├─ ساخت ارجاع فقط از تکه‌های واقعی (C1، C2، ...)
  ├─ هشدارها: داده نمونه/غیررسمی، تزریق دستور، احتمال خطای OCR، نسخه ملغی
  ├─ تشخیص مغایرت احتمالی وقتی ≥۲ سند مستقل منتشرشده به موضوع مربوط‌اند
  ├─ توضیح (لایه ۲): مدل زبانی پیکربندی‌شده یا موتور قالبی آفلاین
  │     ارجاع [C#] خارج از زمینه → حذف + هشدار «ارجاع نامعتبر»
  ├─ وضعیت شخصی (لایه ۳): ارزیابی قواعد تأییدشدهِ مرتبط
  │     چهار وضعیت: برقرار / برقرار نیست / اطلاعات ناکافی / نیازمند بررسی کارشناس
  │     فیلدِ نیازمند تأیید رسمیِ تأییدنشده → نیازمند بررسی (حتی اگر شرط برقرار باشد)
  └─ اقدام بعدی: مراحل فرایند منطبق + «ثبت نهایی فقط در سامانه مقصد»
```

## ۵.۳ قواعد سخت (خط‌قرمزها)

- ارجاع فقط به تکه‌های واقعی بازیابی‌شده؛ سکوت بهتر از استناد ساختگی است.
- سند ملغی هرگز به‌عنوان قانون جاری ارائه نمی‌شود؛ نمایش آن فقط با درخواست صریح و با برچسب و هشدار است.
- «اطلاعات ناکافی» یک خروجی محترم است؛ سال ورود/معدل نامشخص حدس زده نمی‌شود (سناریو ۳).
- متن سند فقط «داده» است؛ دستور داخل آن (تزریق) اجرا نمی‌شود و پرچم می‌خورد (سناریو ۸).
- تصمیم اداری فقط با کارشناس آموزش؛ خروجی قواعد «نیازمند بررسی» را می‌سازد نه تأیید.
- با وجود اسناد غیررسمی، هشدار «نمونه و غیررسمی» در همه پاسخ‌ها نمایش داده می‌شود.

## ۵.۴ اعتبارسنجی پس از مدل زبانی

مدل (در صورت پیکربندی) فقط دو بخش «پاسخ کوتاه» و «شرایط مهم» را می‌نویسد. پس از دریافت:

1. همه `[C#]` استخراج می‌شود؛ هر ارجاعی که به تکه‌های داده‌شده تعلق نداشته باشد حذف و هشدار داده می‌شود.
2. پاسخ بدون هیچ ارجاع → هشدار «منابع بازیابی‌شده خودکار پیوست شد».
3. خطای شبکه/پارس → سقوط شفاف به موتور قالبی (پاسخ همچنان کامل است).
4. نام موتور پاسخ در پایین هر پاسخ نمایش داده می‌شود (شفافیت درباره «چه چیزی پاسخ را تولید کرده است»).
