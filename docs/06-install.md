# ۶) راهنمای نصب و اجرا

## ۶.۱ نسخه وب (پیش‌فرض) — از سورس

پیش‌نیاز: پایتون ۳.۱۰ یا جدیدتر (بیلد فرانت‌اند React از قبل در `frontend/dist` مخزن قرار دارد؛ برای توسعه فرانت‌اند به Node 18+ نیاز است).

```bash
git clone https://github.com/hjalilvand2004-coder/DastyarAmoozeshi.git
cd DastyarAmoozeshi
pip install -r requirements.txt
python run.py            # وب‌اپ: http://127.0.0.1:8600 — مستندات API: /api/docs
```

- در اولین اجرا پوشه `data/` کنار پروژه ساخته و دیتابیس با داده نمونه (غیررسمی) مقداردهی می‌شود.
- محل داده: متغیر محیطی `DASTYAR_HOME` · پورت: `D360_PORT` (پیش‌فرض ۸۶۰۰)
- باز شدن خودکار مرورگر: `python run.py --open`
- رابط دسکتاپ قدیمی: `python run.py --desktop` (نیازمند `pip install -r requirements-desktop.txt`)

## ۶.۲ توسعه فرانت‌اند

```bash
cd frontend
npm install
npm run dev      # http://localhost:5173 با پراکسی /api به 8600
npm run build    # خروجی در frontend/dist (بک‌اند آن را سرو می‌کند)
```

## ۶.۳ بدون نصب پایتون (ویندوز)

فایل پرتابل را از بخش Releases دانلود کنید و `RUN-DastyarAmoozeshi.bat` را اجرا کنید — سرور محلی بالا می‌آید و مرورگر باز می‌شود. راهنمای کامل: [docs/07-portable.md](07-portable.md).

## ۶.۴ حساب‌های نمایشی

| کاربر | رمز | نقش |
|---|---|---|
| admin | Admin@123 | مدیر سیستم |
| expert | Expert@123 | کارشناس آموزش |
| content | Content@123 | مدیر محتوای آیین‌نامه |
| approver | Approver@123 | تأییدکننده |
| student | Student@123 | دانشجو (علی، معدل ۱۴/۵، ورودی ۱۴۰۲) |
| student2 | Student@123 | دانشجوی نمونه با سال ورود نامشخص |

ورود بدون رمز (نمایش SSO): صفحه ورود ← «ورود آزمایشی بدون رمز».

## ۶.۵ ورود یکپارچه دانشگاهی (SSO/OIDC)

مدیر سیستم: «مدیریت سیستم ← تنظیمات» و ثبت این کلیدها:

| کلید | نمونه |
|---|---|
| `sso_oidc_issuer` | `https://sso.university.ac.ir/realms/student360` |
| `sso_oidc_client_id` | `dastyar360` |
| `sso_oidc_client_secret` | (مخفی) |

پس از ثبت، در صفحه ورود دکمه «ورود یکپارچه دانشگاه (SSO)» ظاهر می‌شود. جریان: Authorization Code OIDC (کشف خودکار از `/.well-known/openid-configuration`) → دریافت هویت از userinfo → ایجاد خودکار کاربر در اولین ورود → صدور توکن JWT برنامه. نگاشت نقش از claim نقش‌ها (کلیدواژه expert/approver/content/admin) و پیش‌فرض «دانشجو».

## ۶.۶ چرخه کاری پیشنهادی برای ثبت اسناد رسمی

1. **مدیر محتوا** (`content`): «آیین‌نامه‌ها» ← «ثبت سند جدید» ← متن یا فایل (txt/pdf/docx) + متادیتا ← ثبت (پیش‌نویس).
2. **مدیر محتوا:** «ارسال برای بررسی».
3. **تأییدکننده** (`approver`): «تأیید» سپس «انتشار» — از این لحظه سند برای دانشجویانِ داخل دامنه قابل استناد است.
4. اصلاح آینده: «نسخه جدید» (پیش‌نویس نسخه n+1) و تکرار چرخه؛ متن نسخه منتشرشده هرگز ویرایش نمی‌شود.
5. ابطال: «ابطال» با ذکر دلیل؛ سند از پاسخ‌های جاری حذف و فقط با برچسب ملغی دیده می‌شود.
