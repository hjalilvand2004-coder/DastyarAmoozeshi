## ۲.۲ تصمیم‌های معماری

1. **جداي کامل UI از منطق:** هیچ فایلی در `app/` جز `ui/` و `main.py` PyQt6 را import نمی‌کند. همه امکانات از pytest قابل تست‌اند و منطق برای نسخه وب قابل استفاده مجدد است.
2. **بدون میکروسرویس غیرضروری** (مطابق بند ۱۳ مشخصات): یک دیتابیس، یک فرایند، ماژول‌بندی ساده. جداکردن خدماتی مثل موتور قواعد در آینده فقط با تعویض لایه سرویس ممکن است، نه بازنویسی.
3. **جدایی موتور قواعد از مدل زبانی:** قواعد در دیتابیس به‌صورت JSON هستند و با ارزیابی سه‌حالته (درست/نادرست/نامشخص) کار می‌کنند؛ هیچ تصمیم عملیاتی از خروجی مدل زبانی گرفته نمی‌شود.
4. **مدل زبانی به‌صورت پلاگین:** `TemplateProvider` (پیش‌فرض آفلاین) و `OpenAICompatibleProvider` (اختیاری). هر دو فقط «توضیح» تولید می‌کنند؛ اگر مدل در دسترس نباشد، پاسخ بدون توضیح مولد همچنان کامل و مستند است.
5. **نسخه‌بندی اسناد:** متن نسخه منتشرشده هرگز ویرایش نمی‌شود؛ اصلاح = ساخت نسخه جدید (زنجیره parent_id) با وضعیت پیش‌نویس.
6. **امنیت هوش مصنوعی:** محتوای سند بین تگ‌های داده قرار می‌گیرد، الگوهای تزریق دستور پرچم می‌خورد، ارجاع‌های مدل فقط به تکه‌های واقعی مجازند و نرخ پرسش محدود می‌شود.
7. **جداسازی چنددانشگاهی:** همه رکوردها `university_id` دارند و هر سرویس آن را بررسی می‌کند؛ دسترسی بین‌دانشگاهی در تست پذیرش ۷ رد می‌شود.

## ۲.۳ نقاط یکپارچه‌سازی آینده

| نقطه | وضعیت فعلی | مسیر آینده |
|---|---|---|
| ورود یکپارچه (Keycloak/OIDC) | کاربر محلی با نقش | جایگزینی `services.login` با اعتبارسنجی توکن؛ طرح داده آماده است |
| سامانه آموزشی دانشگاه (انتخاب واحد/کارورزی) | دیتای محلی نمونه | فراخوانی API رسمی از همان توابع `services`؛ تا آن زمان «تأیید رسمی» صادر نمی‌شود |
| تقویم رسمی دانشگاه | رویداد محلی با نسخه‌بندی | همگام‌سازی با تقویم رسمی + اعلان اصلاحات |
| مدل زبانی سازمانی | تنظیمات کاربر | تعویض آدرس/مدل در صفحه تنظیمات |
| نسخه وب | دسکتاپ | همان لایه سرویس‌ها زیر REST (docs/04) |

## ۲.۴ جریان یک پرسش (خلاصه)

پرسش ← پاک‌سازی و محدودسازی نرخ ← انتخاب اسناد کاندید (منتشرشده، داخل بازه اعتبار، منطبق با اسکوپ دانشجو؛ ملغی فقط با درخواست صریح) ← امتیازدهی BM25 روی تکه‌ها ← آستانه اهمیت ← ساخت ارجاع فقط از تکه‌های واقعی ← توضیح (مدل/قالبی) با اعتبارسنجی ارجاع ← ارزیابی قواعد مرتبط ← تطبیق فرایند اداری ← تشکیل پاسخ سه‌لایه با هشدارها و موارد نیازمند تأیید ← ذخیره در تاریخچه گفتگو.
