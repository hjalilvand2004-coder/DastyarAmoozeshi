# استقرار آموزش‌یار۳۶۰ روی سرور سازمانی + ورود یکپارچه پرتال SSO

این سند تنظیمات نهایی نسخه ۰.۴.۰ برای استقرار روی سرور سازمانی و اتصال به پرتال ورود یکپارچه سازمانی (دانشجویار۳۶۰) است.

## ۱) پارامترهای استقرار

| پارامتر | مقدار |
|---|---|
| آدرس عمومی آموزش‌یار۳۶۰ | `http://188.212.96.235:8091/` |
| پورت سرویس | `8091` (پیش‌فرض؛ با `D360_PORT` قابل تغییر) |
| پرتال ورود یکپارچه سازمانی (هاب SSO) | `http://188.212.96.235:8086` |
| Client ID آموزش‌یار۳۶۰ در پرتال SSO | `amoozeshyar360` |
| کلید سامانه (appKey) | `amoozeshyar` |
| نقطه ورود یکپارچه (ثبت در پرتال) | `http://188.212.96.235:8091/api/v1/auth/sso/university/entry` |
| redirect_uri جریان OIDC | `http://188.212.96.235:8091/api/v1/auth/sso/university/callback` |
| مسیر جایگزین فرانت‌اند | `http://188.212.96.235:8091/sso/start` |

پیش‌فرض‌ها در `app/config.py` قرار دارند و به ترتیب «متغیر محیطی ← تنظیم مدیر در رابط ← پیش‌فرض» اعمال می‌شوند:

```bash
export D360_PUBLIC_BASE_URL="http://188.212.96.235:8091"   # آدرس عمومی (مبنای redirect_uri)
export D360_OIDC_ISSUER="http://188.212.96.235:8086"       # پرتال SSO سازمان
export D360_OIDC_CLIENT_ID="amoozeshyar360"
export D360_PORT=8091
export D360_HOST="0.0.0.0"
# اختیاری: اگر پرتال توکن HS256 با رمز مشترک بفرستد:
# export D360_SSO_HUB_SECRET="..."
```

## ۲) اجرای سرویس روی سرور

```bash
cd /opt/AmoozeshYar360        # محل بازکردن مخزن یا بسته پرتابل
pip install -r requirements.txt   # در بسته پرتابل لازم نیست
python run.py
```

نمونه سرویس systemd (`/etc/systemd/system/amoozeshyar360.service`):

```ini
[Unit]
Description=AmoozeshYar360 (Student360)
After=network.target

[Service]
WorkingDirectory=/opt/AmoozeshYar360
Environment=D360_PORT=8091
Environment=D360_HOST=0.0.0.0
Environment=D360_PUBLIC_BASE_URL=http://188.212.96.235:8091
ExecStart=/usr/bin/python3 run.py
Restart=always

[Install]
WantedBy=multi-user.target
```

پورت ۸۰۹۱ باید در فایروال سرور باز باشد:

```bash
firewall-cmd --add-port=8091/tcp --permanent && firewall-cmd --reload
```

## ۳) ثبت سامانه در پرتال SSO سازمانی

در پرتال `http://188.212.96.235:8086` بخش «مدیریت سامانه‌ها» برای آموزش‌یار۳۶۰ این مقادیر را ذخیره کنید:

- **کلید سامانه (appKey):** `amoozeshyar`
- **نام:** آموزش‌یار۳۶۰
- **Client ID در SSO:** `amoozeshyar360`
- **آدرس ورود (نقطه ورود OIDC):** `http://188.212.96.235:8091/api/v1/auth/sso/university/entry`
- **ترتیب:** دلخواه (مثلاً ۶) · **فعال:** بله

تا قبل از ذخیره این رکورد، پرتال برای درخواست‌های OIDC پاسخ «کلاینت ناشناس client_id=amoozeshyar360 در سامانه ثبت نشده است» می‌دهد؛ این پیام یعنی گام سمت پرتال انجام نشده و ایرادی در آموزش‌یار۳۶۰ نیست.

### جریان ورود

1. کاربر از پرتال (یا مستقیم) وارد `http://188.212.96.235:8091/` می‌شود؛ صفحه ورود آموزش‌یار۳۶۰ دکمه «ورود یکپارچه سازمانی (SSO)» را دارد.
2. کلیک (یا ورود از لانچر پرتال) → هدایت به پرتال SSO. اگر نشست پرتال فعال باشد، **بدون وارد کردن رمز** بلافاصله به سامانه برمی‌گردد (ورود بدون رمز).
3. پرتال با کد مجوز به `redirect_uri` برمی‌گردد؛ آموزش‌یار۳۶۰ کد را با **PKCE (S256)** تبادل می‌کند، هویت را از `userinfo` پرتال می‌گیرد و کاربر را در اولین ورود به‌صورت خودکار ایجاد می‌کند.
4. پرتال SSO این نسخه از `authorization_code` + `refresh_token` با `response_type=code` و PKCE `S256` پشتیبانی می‌کند (بر اساس `/.well-known/openid-configuration`).

### نگاشت نقش‌ها از پرتال

قرارداد پرتال «کلید سامانه.نقش» است؛ این نقش‌ها به نقش‌های آموزش‌یار۳۶۰ نگاشت می‌شوند:

| نقش در پرتال | نقش در آموزش‌یار۳۶۰ |
|---|---|
| `amoozeshyar.admin` (یا system_admin/sysadmin) | مدیر سیستم |
| `amoozeshyar.approver` | تأییدکننده آیین‌نامه |
| `amoozeshyar.content` | مدیر محتوای آیین‌نامه |
| `amoozeshyar.expert` | کارشناس آموزش |
| `amoozeshyar.access` یا بدون نقش | دانشجو |

سایر نقش‌ها (مثل `barnamehyar.admin`) اثری ندارند تا هر سامانه فقط نقش‌های خودش را ببیند.

### حالت توکن مستقیم پرتال (اختیاری)

اگر پرتال به‌جای جریان کد، توکن امضاشده به آدرس ورود بفرستد (`?token=...` یا `?jwt=...`)، آموزش‌یار۳۶۰ امضای آن را بررسی می‌کند:

- **RS256:** کلید عمومی از `jwks_uri` پرتال (کش ۱۰ دقیقه) — بدون رمز مشترک.
- **HS256:** با رمز مشترک `sso_hub_secret` (تنظیمات مدیر یا متغیر محیطی).

پس از اعتبارسنجی، نشست برنامه صادر و به `/sso/callback` هدایت می‌شود.

## ۴) پیکربندی مدل زبانی (اختیاری)
